# 03 — Go module restructure

Goal: both modules build, test, and lint from their new locations under their new module
paths, with and without the Go workspace active.

Prerequisite state: [02-history-migration.md](02-history-migration.md) complete. Files
are in their final directories; no file contents have been edited yet.

## Step 1 — remove the `go.work` gitignore entries

Both `.gitignore` files currently contain:

```text
# Go workspace file
go.work
go.work.sum
```

Delete both lines from the root `.gitignore`. Leaving them in place makes `git add go.work`
silently do nothing and the workspace never reaches CI. Do this before creating the
workspace so the file is trackable the moment it exists.

`apps/bean-counter/.gitignore` is merged into the root file in WP9; its copy of these
lines disappears with it.

## Step 2 — rename module paths

`libs/beans/go.mod` line 1:

```text
module github.com/mattsp1290/beans
→
module github.com/mattsp1290/beans/libs/beans
```

`apps/bean-counter/go.mod` line 1:

```text
module github.com/mattsp1290/bean-counter
→
module github.com/mattsp1290/beans/apps/bean-counter
```

Leave the `go 1.25.7` directive in both files unchanged. Both modules already declare
the same Go version as the toolchain on this machine (`go version` reports
`go1.25.7 darwin/arm64`).

## Step 3 — rewrite the intra-repo dependency

`apps/bean-counter/go.mod` currently has, in its first `require` block:

```text
github.com/mattsp1290/beans v0.1.2-0.20260615002029-e52dce57b52c
```

Replace that line and add a `replace` directive:

```text
require (
	github.com/gofiber/fiber/v3 v3.3.0
	github.com/mattsp1290/beans/libs/beans v0.0.0
	github.com/testcontainers/testcontainers-go/modules/mysql v0.42.0
	github.com/testcontainers/testcontainers-go/modules/postgres v0.42.0
)

replace github.com/mattsp1290/beans/libs/beans => ../../libs/beans
```

The `v0.0.0` version is a placeholder. A `replace` to a filesystem path makes the
required version irrelevant to resolution, but a `require` entry must still exist for
the import to be legal.

This replace, not `go.work`, is what makes the container build and every `GOWORK=off`
invocation correct. See decision D3 in [00-overview.md](00-overview.md).

## Step 4 — rewrite imports

The five affected import prefixes are listed in
[01-target-layout-and-module-graph.md](01-target-layout-and-module-graph.md). Rewrite
them across both modules:

```bash
cd "$HOME/git/beans"
grep -rl 'github\.com/mattsp1290/beans/' --include='*.go' libs apps \
  | xargs sed -i '' 's|github\.com/mattsp1290/beans/|github.com/mattsp1290/beans/libs/beans/|g'
```

The trailing slash in the search pattern is required. Without it the pattern also
matches `github.com/mattsp1290/beans` as a bare module path and produces
`github.com/mattsp1290/beans/libs/beans` in places that should not have it, including
`libs/beans/go.mod`'s own module line if that file were in scope.

Run `gofmt -l` and `goimports` afterwards; the longer paths change import-group
alignment.

Non-Go occurrences, each edited by hand:

| File | Before | After |
| --- | --- | --- |
| `libs/beans/Makefile` line 4 | `-X github.com/mattsp1290/beans/version.Version=$(VERSION)` | `-X github.com/mattsp1290/beans/libs/beans/version.Version=$(VERSION)` |
| `libs/beans/.golangci.yml` line 40 | `- github.com/mattsp1290/beans` | `- github.com/mattsp1290/beans/libs/beans` |
| `libs/beans/README.md` lines 300-304 | five `github.com/mattsp1290/beans/<pkg>` examples | `github.com/mattsp1290/beans/libs/beans/<pkg>` |
| `apps/bean-counter/scripts/deploy-production.sh` line 54 | `BEANS_MODULE="github.com/mattsp1290/beans"` | `BEANS_MODULE="github.com/mattsp1290/beans/libs/beans"` |

`apps/bean-counter/.golangci.yml` has no `goimports.local-prefixes` setting, so it needs
no import-prefix edit. Adding one is optional cleanup and is not required by this plan.

The `LDFLAGS` edit is the highest-risk item in this work package. A wrong path there
produces a binary whose `version.Version` stays at its zero value with no build error.
Step 7 verifies it explicitly.

Do not rewrite occurrences under `.agents/`. Those are dated review and plan records.

## Step 5 — create the workspace

```bash
cd "$HOME/git/beans"
go work init ./libs/beans ./apps/bean-counter
go work sync
```

The generated `go.work`:

```text
go 1.25.7

use (
	./apps/bean-counter
	./libs/beans
)
```

Both `go.work` and `go.work.sum` are committed.

When the third application is added, one `use ./apps/<name>` line joins this block. See
[07-third-app-slot.md](07-third-app-slot.md).

## Step 6 — tidy both modules

```bash
cd "$HOME/git/beans/libs/beans"        && GOWORK=off go mod tidy
cd "$HOME/git/beans/apps/bean-counter" && GOWORK=off go mod tidy
cd "$HOME/git/beans"                   && go work sync
```

`GOWORK=off` is deliberate. Running `go mod tidy` with the workspace active can resolve
dependencies through sibling modules and write a `go.sum` that is incomplete when the
module is built alone — which is exactly how the container build runs it.

Expected result in `apps/bean-counter/go.sum`: every `github.com/mattsp1290/beans` entry
disappears. The dependency is now satisfied from the filesystem, and a replaced module
contributes no checksum. Its transitive requirements — `gorm.io/*`, `github.com/glebarez/*`,
`github.com/jackc/pgx/v5`, `github.com/pressly/goose/v3`, `github.com/go-sql-driver/mysql`
— remain, because `apps/bean-counter` still builds them.

`libs/beans/deps.go` is a `//go:build tools` file that pins `gorm.io/*`,
`github.com/glebarez/sqlite`, and the testcontainers MySQL module. `go mod tidy` respects
build-tagged files only when the tag is satisfied. Verify after tidying that
`libs/beans/go.mod` still requires those modules; if `tidy` dropped them, restore them
with `go get` and record why in the commit message.

## Step 7 — verification

Run all of these. Each must pass.

```bash
cd "$HOME/git/beans"

# Workspace-wide build.
go build ./libs/beans/... ./apps/bean-counter/...

# Each module standalone, workspace disabled. This is the container's view.
( cd libs/beans        && GOWORK=off go build ./... && GOWORK=off go test ./... )
( cd apps/bean-counter && GOWORK=off go build ./... && GOWORK=off go test ./... )

# Vet and lint per module.
( cd libs/beans        && go vet ./... && golangci-lint run ./... )
( cd apps/bean-counter && go vet ./... && golangci-lint run ./... )

# No stale module path outside the historical record.
grep -rn 'github\.com/mattsp1290/beans[^/]' --include='*' . \
  | grep -v '^\./\.git/' | grep -v '^\./\.agents/'
# must print nothing

grep -rn 'github\.com/mattsp1290/bean-counter' --include='*' . \
  | grep -v '^\./\.git/' | grep -v '^\./\.agents/'
# must print nothing

# The LDFLAGS path is correct: version is non-empty.
( cd libs/beans && make build && ./bin/bn version )
# must print a version derived from git describe, not an empty string
```

The first grep's `[^/]` guard excludes the new correct paths, which all continue with
`/libs/beans/` or `/apps/bean-counter/`. It does match `github.com/mattsp1290/beans"`
and `github.com/mattsp1290/beans ` — the bare old module path — which is what must be
gone. It will also match the repository URL in a `git remote` line if one is grepped;
`.git/` is excluded for that reason.

Confirm the exact subcommand name before relying on the last check. If `bn` exposes the
build version under a different subcommand or flag, use that instead and record it here.
The requirement is that the version string is non-empty, not that a particular
subcommand exists.

## Acceptance criteria

1. `go build ./...` and `go test ./...` pass in each module with `GOWORK=off`.
2. `go vet` and `golangci-lint run` are clean in each module.
3. `go.work` and `go.work.sum` are tracked by git.
4. `apps/bean-counter/go.mod` contains the `replace` to `../../libs/beans`, and
   `apps/bean-counter/go.sum` contains no `github.com/mattsp1290/beans` entry.
5. `libs/beans/go.mod` still requires `gorm.io/gorm`, `gorm.io/driver/mysql`,
   `gorm.io/driver/postgres`, `gorm.io/datatypes`, `github.com/glebarez/sqlite`, and
   `github.com/testcontainers/testcontainers-go/modules/mysql`.
6. Both verification greps print nothing.
7. The `bn` binary built by `make build` in `libs/beans` reports a non-empty version.

## Risks and edge cases

- **`sed -i ''` is BSD syntax.** It is correct on this Darwin machine and wrong on
  GNU/Linux. If the migration is executed elsewhere, use `sed -i` without the empty
  argument.
- **`go mod tidy` may drop the `deps.go` pins.** Step 6 checks for this explicitly.
- **Integration tests are behind a build tag.** `go test ./...` does not compile them.
  `go test -tags=integration ./...` in `libs/beans` and
  `go test -tags=integration ./test/integration` in `apps/bean-counter` require Docker
  and are gated in [04-build-lint-and-ci.md](04-build-lint-and-ci.md), not here.
